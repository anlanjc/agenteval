# ADR：多版本对比评测（A/B 实验核心件）

> 状态：已实现（2026-10-28）｜实现：agenteval/compare.py + tests/test_compare.py（9 项）
> 全量测试 80 项全绿（71 既有 + 9 新增）

## 1. 我为什么做"对比评测"而不是只做"回归门禁"

门禁回答的是"这版能不能上线"（二元判定），但面试必答题是"**你说优化了，优化了多少、怎么测的**"——这需要一个能同时回答三个层的工具：指标层差多少、哪些用例翻转变了、输出内容漂移没有。对比评测就是把 gate 从"守门员"升级成"实验记录仪"：同数据集跑两个版本，产出可讲解、可存档的 diff 报告。

## 2. 设计决策

### 2.1 指标对比直接复用 gate 的方向感知逻辑
- **决策**：compare_metrics 是现成的"方向感知 + 阈值"实现，对比评测原样复用（delta 语义一致），不另写一套。
- **理由**：两处口径不一致是评测平台的经典腐败起点——门禁说"没劣化"、对比说"劣化了"，用户该信谁？
- **代价**：对比报告里的 FAIL 字段继承门禁阈值语义（超阈值才标 FAIL）——但对比报告的重点是 delta 本身，FAIL 只是参考列。

### 2.2 逐用例对齐产出三类信号
1. **回归（pass→fail）**：最危险，逐条列出 judge 判定理由（overall/分维度/原因前 80 字）。
2. **修复（fail→pass）**：优化叙事的证据。
3. **输出漂移（判定未翻但输出不同）**：这是我最看重的一类信号——**两版都通过但答案不一样，说明模型行为变了**。可能无害（更详细的表述），也可能是语义回归的早期征兆（换了个引用来源）。门禁看不见它，对比评测让它显形。

### 2.3 硬性前置校验：数据集与用例集必须一致
- 数据集名不一致、用例集合不一致直接 raise——**A/B 对比的大忌是拿不同数据集的分数互比**。报错信息里写明差异，不静默。
- 数据集版本号（dataset_version）随报告走，报告 JSON 里可追溯。

### 2.4 落盘双格式
- `.json`（结构化，供 CI/程序消费）+ `.md`（人读，含指标表、修复/回归明细、输出漂移清单、延迟变化 Top10）——报告要同时喂机器和人。

## 3. 一个设计取舍的诚实记录

延迟对比是**逐用例**的（候选-基线，毫秒级），但 LLM 延迟噪声大（同一版重跑也能差 ±30%）——所以报告只列 Top10 绝对值变化，并在门禁层对 P50/P95 设了大阈值（1s/2s）。**逐用例延迟差不要拿来做单点结论，要看分布**；真正的延迟结论应该用 P95 delta + 足够多的重复次数。

## 4. 使用方式

```python
from agenteval.compare import compare_runs, compare_report_files
rep = compare_runs(baseline_report, candidate_report)   # 内存对象直比
rep = compare_report_files("base.json", "cand.json")    # 从落盘报告比
rep.render_markdown()   # 贴 CI 评论/面试讲稿
rep.save("eval/compare_v1_v2")  # .json + .md 双落盘
```

CLI 接入（`agenteval compare` 子命令）列为下一版——函数层已就绪。

## 5. 与门禁的分工

| 场景 | 用 gate | 用 compare |
|---|---|---|
| 提交后自动判断能否合并 | ✅（exit code） | 参考列 |
| 讲清楚"这版改了什么、影响了哪些 case" | ❌ | ✅ |
| 发现语义漂移（都通过但行为变了） | ❌ | ✅ |
| 实验记录存档 | 部分 | ✅ |


## 6. 生态导出（ADR 下一版清单落地，2026-10-28）

trace 的可观测性不锁死：`agenteval/export.py` 把落库 run 转成 **Langfuse 兼容事件 JSONL**（trace-create + span-create，字段对齐其 ingestion 约定；离散事件降级为瞬时 span）。生产接 Langfuse = 这一层导出 + 推送，评测的语义结构（run→case→target.call→judge.score）在两家体系同样可读。测试 5 项（结构/父子链接/落盘往返/全量导出/未知 run）。


## 7. 金丝雀监控（A10，2026-10-28）

线上常驻小评测：`agenteval/canary.py`——每 K 次生产调用触发一次 N 条抽样评测（固定 seed 可比），滑动窗口通过率 vs 基线（首窗均值或显式设定）容差判定，劣化即告警回调。与 gate 同源的方向感知口径——**离线门禁与在线监控一套语义**。捕的是第四种故障形态：报错能触发重试，静默劣化只能靠它。测试 5 项（触发节律/窗口/告警/恒定不误报/显式基线）。
